# Эмулятор оболочки UNIX

Учебный проект по дисциплине «Конфигурационное управление», вариант 4.
Консольное приложение на Python 3, имитирующее работу командной строки
UNIX-подобной ОС.

## Общее описание

Эмулятор работает в режиме REPL: показывает приглашение с именем виртуальной
файловой системы (VFS), читает команду, выполняет её и снова ждёт ввода.
Поддерживается настройка через параметры командной строки, стартовый скрипт
и загрузка VFS из ZIP-архива. Все операции с VFS выполняются в памяти.
Текущий этап: **Этап 3 — VFS** (команды ls и cd пока заглушки).

## Функции

- Приглашение к вводу содержит имя VFS: `deep$`, `vfs$`.
- Парсер разбивает строку на слова, понимает кавычки (`"my dir"`) и
  раскрывает переменные окружения реальной ОС: `$HOME`, `${USERNAME}`.
  Неизвестная переменная заменяется пустой строкой. Если переменная `HOME`
  не задана (Windows), используется домашняя папка пользователя.
- Команды-заглушки `ls` и `cd` выводят своё имя и аргументы.
- `vfs-init` заменяет текущую VFS на VFS по умолчанию и сбрасывает путь
  к файлу VFS (сам файл на диске не изменяется).
- `vfs-info` (служебная команда) показывает источник, каталоги и файлы
  текущей VFS.
- `exit` завершает работу.
- Ошибки: неизвестная команда, незакрытая кавычка, лишние аргументы
  `vfs-init`, неверный или отсутствующий файл VFS.
- При запуске выводится отладочная информация обо всех параметрах.
- Стартовый скрипт выполняется построчно, на экране показываются и ввод,
  и вывод. Пустые строки и комментарии (`#`) пропускаются, ошибочные строки
  выдают сообщение и пропускаются. Если в скрипте встретился `exit`,
  эмулятор завершается, иначе после скрипта открывается интерактивный режим.

## Виртуальная файловая система

Источник VFS — ZIP-архив. Он читается целиком в память (`zipfile` поверх
`io.BytesIO`), на диск ничего не распаковывается и не записывается.
Файл, указанный в `--vfs`, может быть:

- обычным ZIP-архивом;
- текстовым файлом с ZIP в кодировке base64 (так хранятся тестовые VFS,
  чтобы в репозитории не было бинарных файлов и архивов).

Имя VFS берётся из имени файла без расширения. Без параметра `--vfs`
используется встроенная VFS по умолчанию (имя `vfs`).

Тестовые VFS в папке `data` создаёт генератор:

    py tools\make_vfs.py

| Файл                     | Содержимое                                   |
|--------------------------|----------------------------------------------|
| `data/minimal.b64`       | минимальная VFS: один файл                   |
| `data/several_files.b64` | четыре файла                                 |
| `data/deep.b64`          | 9 каталогов, 7 файлов, вложенность до 5      |
|                          | уровней, двоичный файл                       |
| `data/broken.b64`        | корректный base64, но не ZIP (для проверки   |
|                          | ошибки)                                      |

## Настройки (параметры командной строки)

| Параметр        | Описание                                       |
|-----------------|------------------------------------------------|
| `--vfs ПУТЬ`    | путь к физическому расположению VFS (ZIP или   |
|                 | base64-текст ZIP)                              |
| `--script ПУТЬ` | путь к стартовому скрипту                      |
| `-h`, `--help`  | справка                                        |

Оба параметра необязательны.

## Запуск

Требуется Python 3.9 или новее.

- Windows: `run.bat [параметры]` (или `py src\main.py [параметры]`)
- Linux/macOS: `sh run.sh [параметры]` (или `python3 src/main.py ...`)

Скрипты ОС для проверки лежат в папке `scripts`:

    scripts\test_vfs_minimal.bat   минимальная VFS
    scripts\test_vfs_several.bat   VFS с несколькими файлами
    scripts\test_vfs_deep.bat      глубокая VFS и все команды этапа
    scripts\test_vfs_errors.bat    ошибки загрузки VFS
    scripts\test_script.bat        параметр --script
    scripts\test_all.bat           все параметры, --help, ошибки

Стартовые скрипты эмулятора: `scripts\startup_basic.emu`,
`scripts\startup_errors.emu`, `scripts\startup_stage3.emu` (все команды
этапа 3, включая VFS и ошибки), `scripts\vfs_info.emu`.

## Тесты

Из корня проекта:

    py -m unittest discover -s tests -t .

На Linux/macOS вместо `py` используйте `python3`.

## Примеры использования

    py src\main.py --vfs data\deep.b64

    [отладка] Параметры запуска:
    [отладка]   --vfs    = data\deep.b64
    [отладка]   --script = <не задан>
    deep$ vfs-info
    VFS «deep», источник: data\deep.b64
    каталогов: 9, файлов: 7
      [dir]  etc/
      ...
      [file] home/user/pics/icon.bin (16 байт)
    deep$ vfs-init
    vfs-init: загружена VFS по умолчанию
    vfs$ vfs-init лишний
    vfs-init: команда не принимает аргументов
    vfs$ exit

Ошибка загрузки VFS:

    py src\main.py --vfs data\broken.b64
    Ошибка загрузки VFS: повреждённый или неверный ZIP-архив

## Структура проекта

- `src/main.py` — точка входа
- `src/config.py` — параметры командной строки и отладочный вывод
- `src/session.py` — состояние сеанса (текущая VFS и путь к ней)
- `src/vfs.py` — VFS в памяти, загрузка из ZIP/base64
- `src/shell.py` — выполнение строк, стартовый скрипт, цикл REPL
- `src/cmd_parser.py` — разбор строки и раскрытие переменных
- `src/commands.py` — команды эмулятора
- `tools/make_vfs.py` — генератор тестовых VFS
- `data/` — тестовые VFS (base64)
- `scripts/` — стартовые скрипты (`*.emu`) и скрипты ОС для проверки
- `tests/` — модульные тесты
- `run.bat`, `run.sh` — скрипты запуска
